# GitHub Copilot Context Configuration

## Developer Profile
- **Experience Level**: Experienced C++ developer
- **Language Preference**: English for all comments and documentation
- **Code Style**: Modern C++ (C++17/C++20/C++23), favor simplicity and readability

## Code Preferences

### Modern C++ Standards
- Use C++23 features when available
- Prefer standard library solutions over custom implementations
- Use `auto` where it improves readability
- Favor RAII and smart pointers (`std::unique_ptr`, `std::shared_ptr`)
- Use range-based for loops and standard algorithms
- Prefer `std::format` and `std::print` over C-style formatting

### Simplicity Guidelines
- Write clear, self-documenting code
- Keep functions small and focused (single responsibility)
- Avoid unnecessary complexity and over-engineering
- Prefer composition over inheritance
- Use standard containers (`std::vector`, `std::array`) over raw arrays
- Minimize manual memory management

### Code Style
- **Comments**: Always in English
- **Naming**: 
  - Classes: PascalCase
  - Functions/methods: PascalCase or camelCase (match existing codebase)
  - Variables: snake_case or camelCase (match existing codebase)
  - Constants: UPPER_SNAKE_CASE or kPascalCase
- **Comments**: Only when necessary to explain "why", not "what"
- **Documentation**: Use clear, concise English

### Platform Considerations
- Windows development environment
- CMake build system (Ninja generator)
- wxWidgets for GUI
- OpenGL for graphics rendering

## Avoid
- C-style casts (use `static_cast`, `dynamic_cast`, etc.)
- Raw pointers for ownership
- Manual memory management (`new`/`delete`)
- `NULL` (use `nullptr`)
- Macros when templates or constexpr can be used
- Verbose comments that restate code
- Hungarian notation
- Legacy C++ patterns (pre-C++11)

## Prefer
- Stack allocation over heap when possible
- `constexpr` for compile-time constants
- `std::optional` for optional values
- `std::variant` for type-safe unions
- Structured bindings for tuple-like returns
- Lambda expressions for inline callbacks
- Range-based algorithms from `<algorithm>` and `<ranges>`

## Error Handling
- Use exceptions for exceptional situations
- Use `std::expected` (C++23) or `std::optional` for expected failures
- Provide clear error messages in English
- Avoid error codes when exceptions are appropriate

## Concurrency
- Prefer `std::thread`, `std::mutex`, `std::lock_guard`
- Use `std::atomic` for lock-free operations
- Consider `std::jthread` (C++20) for automatic joining

## Testing & Quality
- Write testable code (small, focused functions)
- Minimize side effects
- Favor pure functions when possible
- Consider const-correctness

## Documentation Style
When documentation is needed:
- Keep it concise and in English
- Focus on API contracts and usage
- Document preconditions, postconditions, and invariants
- Avoid restating what the code already says clearly
